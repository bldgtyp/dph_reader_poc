# corpus/adelphi — the primary corpus: one building, six formats

The same real building (a Brooklyn townhouse project) across every format this project cares
about. **These are irreplaceable references — hard rule 3: never modify one, never open a corpus
original in SketchUp for tool work; copy first** (POC convention: copies into
`~/Desktop/dph_poc_copies/`).

| File | Role | Notes |
|---|---|---|
| `adelphi-designph.skp` | ★ **Primary input.** designPH **2.1.15**, SketchUp 2021-era save | 1441 faces carry `DesignPH_dict`; only **82** are classified (the other 1359 are `areaGroupID='n'`). 46 DC windows, 0 thermal bridges, 40 TFA markers, tier-2 assemblies only (`assemblies_ud`, no layer tables). ⚠ **The simplest model in the corpus — it has masked three separate harness bugs. Never validate a rule on it alone** (`00_Context/CONSTRAINTS.md` §9) |
| `adelphi-honeybee-json.hbjson` | Reference output **shape** | From the *Rhino route*: 6 solid rooms, 52 faces, 44 apertures, 38 spaces, 1287 orphaned shades. ⚠ **A shape reference, never an equality target** — v1/POC emit one non-solid Room by design. ⚠ **No longer loads** under current honeybee-ph (`KeyError: 'tfa_override'`) — do not use as a load fixture (`00_Context/HONEYBEE_STACK.md` §6.3) |
| `adelphi-phpp.xlsm` | Numerical ground truth | U-values, areas, TFA. Read with `openpyxl(data_only=True)` via the `phi-rules` skill's cell maps — never hand-explore it. Extracted CSVs: `planning/01_sketchup-export/feasibility/RESULTS/phpp/` |
| `adelphi-designph_PHPP10.ppp` | **Reference by eye; validation reads only** | ⛔ **Hard rule 1 (amended 2026-08-31): never an input route** — extraction of designPH-computed data needs PHI §2.4(d) authorisation; validation reads of our own exports are permitted. Reasoning: `00_Context/PPP_EXPORT.md` §1. ⚠ Exported by designPH **2.4.0 BETA PRO** while the `.skp` beside it is 2.1.15 — not two views of one tool |
| `adelphi-rhino.3dm` | Rhino-route equivalent | The geometry the reference HBJSON came from |
| `adelphi-grasshopper.gh` | Rhino-route equivalent | The GH definition of that route |

⚠ **The formats are only approximately aligned.** Different tools, different dates, different
operators — a numerical mismatch between them is **not** by itself evidence of a bug
(`DESIGNPH-PLUS_PRD.md` §11 caveats).

## Where the derived data lives

- Key-by-key offline baseline of the `.skp` (with all 13 other corpus models):
  `planning/01_sketchup-export/feasibility/RESULTS/PHASE-0_corpus-baseline.md` + `baselines/corpus_baseline.json` — **check there
  before opening the model by hand.**
- Live contract-v2 extraction, translated HBJSON and report: `pocs/01_sketchup-export/_private/fixtures/` (gitignored
  client data, tracked by `pocs/01_sketchup-export/_private/MANIFEST.md`).
- PHPP ground-truth CSVs: `planning/01_sketchup-export/feasibility/RESULTS/phpp/`.
- Reference-HBJSON shape analysis: `planning/01_sketchup-export/feasibility/RESULTS/reference_hbjson_shape.md`.

## Reading the `.skp` without SketchUp

`00_Context/tools/skp_attr_dump.py` (attribute dictionaries) and
`00_Context/tools/skp_decode_tables.py` (the model-level Marshal tables), both PEP 723 `uv run`.
⚠ Pass `re.DOTALL` to any new regex over raw `.skp` bytes, and remember the `.skp` is a **zip** —
a raw byte scan of the container finds nothing (`CLAUDE.md`, "things that have bitten us").
