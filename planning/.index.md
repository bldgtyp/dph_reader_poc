# planning — DesignPH-PLUS

Two bodies of work live here:

1. **The de-risking spike plan** (Phases 0–5) — Phases 0–3 are **complete**; Phases 4–5 are
   **tabled** (Ed, 2026-08-19), see Status below.
2. **[`POC/`](POC/.index.md) — the proof of concept, ✅ complete**: phased implementation plans for
   a POC that builds a valid HBJSON from a real designPH model inside SketchUp. **All five phases
   closed PASS and Ed closed the POC 2026-08-21** — 545/545 faces, 239/239 windows, 99/99 thermal
   bridges across five real models, verified in production ph-navigator and Rhino/Grasshopper.
   The retro and the ranked "what v1 must do differently" list:
   [`POC/RESULTS/POC-5_results.md`](POC/RESULTS/POC-5_results.md).

⚠ **The spike phase docs describe what was *planned and learned in 2026-08-19*, not current
behaviour.** Several of their conclusions were overturned by the POC's real-model runs — the window
rectangle, the `*ID`/`*Auto` exclusivity claim, `loops.size > 1` as a host test. For what is true
now, read [`../00_Context/`](../00_Context/.index.md); these files are the record of how it was
arrived at.

For the spike plan, **read [`00_OVERVIEW.md`](00_OVERVIEW.md) first** — it carries the sequencing,
the evaluation protocol, and the standing rules that apply to every phase.
