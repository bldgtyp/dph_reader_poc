# planning — one project, multiple POCs, one shared knowledge base

This repo is the research record for **DesignPH-PLUS**: reading (and eventually writing) designPH
data as standard HBJSON. The work runs as a sequence of **numbered POCs**, each with its own folder
here, each feeding one shared foundation layer — [`../00_Context/`](../00_Context/.index.md), which
records *what is true*, while these folders record *what happened and how we found out*.

| Folder | POC | Status (2026-08-31) |
|---|---|---|
| [`01_sketchup-export/`](01_sketchup-export/.index.md) | Read a designPH model **inside SketchUp** (Ruby collector + Pyodide translator) and write valid HBJSON | ✅ **CLOSED PASS** (Ed, 2026-08-21) — 545/545 faces, 239/239 windows, 99/99 bridges on five real models; verified in ph-navigator and Rhino/Grasshopper |
| [`02_headless-reader/`](02_headless-reader/.index.md) | The same read with **no SketchUp at all** — a headless C-SDK service (pholio's Dropbox-watcher model) | ✅ Spikes A + B **PASS** (2026-08-29); Spike C (deployment) open; ⛔ SDK access + licensing block commercial use |
| [`03_load-from-phnav/`](03_load-from-phnav/.index.md) | **Reverse direction:** SketchUp *loads* data *from* PH-Navigator | ▶ **Next — being scoped.** Stub only |
| [`spikes/`](spikes/.index.md) | Throwaway spike **code** for all of the above, kept regardless of outcome. Its `.index.md` maps each subfolder to its POC | — |

Conventions for this folder (and how they deviate from the house planning canon):
[`.instructions.md`](.instructions.md).

## The rule

**Do not start a phase, spike, or POC until the previous gate has been evaluated and recorded in
the owning POC's `RESULTS/`.** The sequence exists to stop early, not to complete itself. Each POC
folder keeps its own status table; this file only routes.
