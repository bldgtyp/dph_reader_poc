# planning/.instructions.md — conventions for this folder

House canon: the **`planning-conventions`** skill (`~/.claude/skills/planning-conventions`). This
file declares where this repo deviates, and per the canon, this file wins here.

## What this repo is

A **research record**, not a feature-flow repo. The unit of work is a **POC** (a numbered
`NN_slug/` folder), not a feature/bug packet. POCs are sequenced and gated; closed POCs stay in
place as the permanent record rather than moving to an `archive/` — their evidence is what the repo
*is*.

## Declared deviations

- **Routers are `.index.md`, not `README.md`/`STATUS.md`** — the repo-wide house convention
  (check `.index.md` before processing any folder) predates the canon and every folder here
  already follows it. Status tables live in each POC's `.index.md`; the master table is in
  [`planning/.index.md`](.index.md).
- **No `features/` / `bugs/` / `refactor/` / `archive/`** — see above. If defect-style work ever
  appears here, use the canon's shapes.
- **No GitHub-issue layer.** The remote (`bldgtyp/dph_reader_poc`) is a shared review copy; work
  is driven from these files, and client-derived evidence must never reach an issue anyway.
- **Spike code lives in `planning/spikes/<area>/`**, kept regardless of outcome (AGENTS.md).
  Client-data scratch goes in a gitignored `_private/` beside the code, tracked by a `MANIFEST.md`.

## Rules the canon and this repo share

- One folder per unit of work; results (`RESULTS/`) are written **before** the next gate opens,
  negative results included.
- Durable outcomes fold into the canonical layer in the same pass — here that layer is
  [`../00_Context/`](../00_Context/.index.md) (this repo's `context/`), plus the `phi-rules`
  corpus for generalised designPH facts.
- Front matter / header blocks carry a date and status; get dates from `date`, never from memory.
