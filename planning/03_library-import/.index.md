# planning/03_library-import — POC #3: writing assemblies and window types INTO designPH

**▶ STATUS: Scoped (2026-08-31) — outline written, no spike started.**

POCs #1 and #2 proved the read direction. This POC asks the write direction, narrowly: **can we
SET designPH library data at the model level** — assemblies, window frames, glazings, written into
the model's `DesignPH_dict` from outside — **such that designPH lists it, computes with it, and
carries it to PHPP?** If yes, the product shape is *PH-Navigator builds the library, the model
imports it*, replacing designPH's laborious assembly builder and window editor for BLDGTYP work.

**Read [`00_LIBRARY-IMPORT_OVERVIEW.md`](00_LIBRARY-IMPORT_OVERVIEW.md)** — the verified facts
(what the record already proves about where and how this data is stored), the six open questions
O-1…O-6, the three spikes, the scoped amendment to hard rule 2, and the licensing tasks.
