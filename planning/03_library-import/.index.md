# planning/03_library-import — POC #3: writing assemblies and window types INTO designPH

**⭐ STATUS: Spikes L-A AND L-B both PASS (2026-08-31 — both scoped, built, run and graded in
one day).** designPH accepts foreign model-level library writes end to end (L-A), and **real
PH-Navigator assemblies and window types reproduce their intended U-values + Error % exactly in
designPH's own calculator** (L-B, 8/8 incl. multi-section, two models, both base64 styles). The
mapping contract is **FROZEN v1** (`CONTRACT_phn-library.md`); durable facts:
`00_Context/DESIGNPH_DATA_MODEL.md` §14 + §14.7. **▶ L-C is next, reshaped 2026-08-31 (Ed):
scope the v-0 "Library Sync" product — a small pull-based SketchUp extension consuming PHN.**

POCs #1 and #2 proved the read direction. This POC asks the write direction, narrowly: **can we
SET designPH library data at the model level** — assemblies, window frames, glazings, written into
the model's `DesignPH_dict` from outside — **such that designPH lists it, computes with it, and
carries it to PHPP?** If yes, the product shape is *PH-Navigator builds the library, the model
imports it*, replacing designPH's laborious assembly builder and window editor for BLDGTYP work.

**Read [`00_LIBRARY-IMPORT_OVERVIEW.md`](00_LIBRARY-IMPORT_OVERVIEW.md)** — the verified facts
(what the record already proves about where and how this data is stored), the nine open questions
O-1…O-9 (acceptance, write timing / hot-swap, rename integrity, entity-dictionary coupling), the
three spikes, the scoped amendment to hard rule 2, and the licensing tasks.

**The primary deliverable is what we learn, written down** (Ed, 2026-08-31): spike code is
throwaway and its quality is irrelevant, but every observation is recorded in `RESULTS/`, durable
facts flow to `00_Context/` and `phi-rules`, and any doc a finding contradicts gets corrected and
marked superseded in the same pass.
