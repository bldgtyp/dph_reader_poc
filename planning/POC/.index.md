# planning/POC — proof-of-concept implementation plans

Phased implementation plans for the DesignPH-PLUS POC: one menu item in SketchUp 2022 that reads a
real designPH model and writes a valid HBJSON plus a translation report. Written for handoff to a
coding agent. **Read [`00_POC_OVERVIEW.md`](00_POC_OVERVIEW.md) first** — scope, the two standing
assumptions, architecture, rules, and the definition of done.

Two things in the output are known-imperfect, reported rather than hidden, and belong to **v1**:

- **A framed assembly's U-value cannot be represented in honeybee.** A layer's conductivity is one
  number, so the construction carries the section-1 value — 8 % low on Linde's `06ud`. designPH's
  real figure travels on the report as `u_value_iso6946`. Arguably an upstream honeybee-ph question,
  since `divisions` exists for this and computes the optimistic bound
  ([`RESULTS/POC-3_results.md`](RESULTS/POC-3_results.md) §10.5).
- **TFA marker faces sit inside the envelope Room**, where honeybee defaults a `Floor` to `Ground` —
  so a floor-area marker reads downstream as ground-coupled envelope
  ([`../../00_Context/DATA_CONTRACTS.md`](../../00_Context/DATA_CONTRACTS.md) §5.1).

## 1. ✅ POC-1, POC-2, POC-3 — done *(2026-08-21)*

Recorded in [`RESULTS/`](RESULTS/). The short version of what those phases cost and bought:

- **Two SketchUp sessions, as budgeted — but not as planned.** Session A was meant to answer three
  contract questions *and* capture all five models. It answered two and its captures had to be
  thrown away, because the same session exposed two design errors in the contract. ⚠ **Budget a
  re-capture into any session that also asks an open question.**
- **The first real export changed the documentation more than the code.** Four inferred rules were
  wrong: the aperture rectangle, the window transform, `is_horizontal`, and `face.area` vs the loops.
- **Then the reconciler failed on three of four real captures and the data was right every time.**
  Two checks compared the wrong quantities and one flagged an override pair as a contradiction.
  Adelphi masked all three.
- **A screenshot of designPH's own dialog settled what analysis had got wrong** — the multi-section
  U-value method, and the unit of `surf2_percentage`. When designPH's UI can answer a question about
  designPH's data, ask it before deriving it.

## 2. ✅ POC-4 — closed PASS *(2026-08-21)*

Everything in [`POC-4_integration.md`](POC-4_integration.md) §1–§2 shipped: the two-stage version
gate (`poc/ext/dph_plus_poc/gate.rb`), the payload refusal, atomic writes, output naming that never
touches `model.path`, the dialog's report summary, and the cross-host identity check
(`make identity`). Full record and the gate table in
[`RESULTS/POC-4_results.md`](RESULTS/POC-4_results.md).

Five things worth carrying:

- ⚠ **The gate's own wording had to change, and that is the honest part.** "Byte-identical across
  hosts" is unachievable and was never a *host* problem — the same translation twice on one CPython
  gives two files. Graded on **canonical** identity instead, with raw byte-identity measured and
  reported (§3 of the results).
- ⚠ **Four defects this phase were the same defect**: an assertion on a *call* standing in for an
  assertion on a *surface*. Two of them had been green in CI since the day the fixture was written.
- ⛔ **The progress signal cannot work** and is carried to v1 (§6.7). Fixing it means chunking the
  walk across `UI.start_timer` — i.e. turning `collector.rb`'s recursion into an explicit stack.
- **The version gate runs twice on purpose.** A 3.x model must be refused before a 2.x-shaped
  collector meets a schema it has never seen; "no stamp" is only "not a designPH model" once the
  census comes back empty. C2 confirmed the first half live: **no dialog opened at all**.
- **A tool that drives another tool inherits where it writes.** `byte_identity.py` put real client
  HBJSON into a committed directory by taking `verify_in_chrome.py`'s default. Caught by reading
  `git status`, not by a check.

Still deferred from POC-1 §8, neither urgent: **every dialog open re-downloads the 18 MB runtime**
(fresh port + fresh token + `no-store`), and the HBJSON still crosses the bridge inside a JSON
envelope — Adelphi's output is **324 KB**, up from 96 KB, now that the apertures and the TFA space
are in it. C1 added a third: a refused model still pays the ~2.5 s Pyodide boot before anything
checks it.

## 3. ✅ POC-5 — closed PASS, and the POC with it *(2026-08-21)*

[`RESULTS/POC-5_results.md`](RESULTS/POC-5_results.md). The retro re-measured the corpus off the
frozen translator, assembled the ranked v1 list (§4), and closed the two questions POC-4 handed it:
the **identifier question** (ph-navigator never keys on `properties.ph.*.identifier` and never
matches across uploads — the uuid churn is harmless, §3.3) and **D-1**
(`global_construction_set` is discarded by honeybee-energy itself on load). The ph-navigator check
also produced **Finding 71** — the viewer skips faces whose construction uses a no-mass material,
so tier-2 models render without their envelope (`00_Context/HONEYBEE_STACK.md` §6.4) — and the
Bluff Reach control rendered whole, 194/194 faces with all 40 apertures on their hosts.
