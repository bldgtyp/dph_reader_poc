# poc/ — the DesignPH-PLUS proof of concept

The code the plans in [`../planning/POC/`](../planning/POC/) describe. **Internal only, never
distributed** — the AGPL question blocks release, not private work
([`../planning/POC/00_POC_OVERVIEW.md`](../planning/POC/00_POC_OVERVIEW.md) §2.3).

Start with `make ci` — it is the whole offline gate, and it names what it cannot reach.

▶ **Status lives in [`../planning/POC/.index.md`](../planning/POC/.index.md)**, not here.
✅ **The POC is complete — all five phases closed PASS, Ed closed it 2026-08-21.** This code ran
end to end in SketchUp 22.0.353 against all five corpus models — 545/545 classified faces, 239/239
windows, 99/99 thermal bridges, both U-value regressions PASS — the wired export path was exercised
live across four sessions, and the output was verified in production **ph-navigator** and in
Rhino/Grasshopper on an independent honeybee install. The contract is **frozen at v2**. This code
is now a *reference implementation* for a future V-0, not an active workstream; the ranked list of
what a V-0 must do differently is [`../planning/POC/RESULTS/POC-5_results.md`](../planning/POC/RESULTS/POC-5_results.md) §4.

⛔ **One known-broken feature**: the progress signal. No indicator can update during the collector
walk, because it is synchronous on SketchUp's main thread. Kept, documented as non-functional, and
carried to v1 (`00_Context/SKETCHUP_RUNTIME.md` §5 rule 3).

| `ext/tests/test_static_server.rb` | Drives the real loopback server over a real socket (19 checks) |
| `ext/tests/test_collector.rb` | Every collector rule that would otherwise lose data silently (82 checks) |
| `ext/tests/test_gate.rb` | Both refusal tables, the safe-name rules, and atomic writes (74 checks) |
| `ext/tests/test_integration.rb` | A whole export driven against a stubbed `HtmlDialog`, reading the **message boxes** back — which is how "failures surface visibly" gets a pass/fail (54 checks) |

| `tools/vendor_payload.py` | Downloads and pins the Pyodide 0.24.1 payload into `vendor/` |
| `tools/build_rbz.py` | Stages the payload, zips the translator, writes `build_info.json`, builds `dist/dph_plus_poc.rbz`. `--check` catches a stale staged translator |

Generated and gitignored: `vendor/`, `ext/dph_plus_poc/vendor/`, `ext/dph_plus_poc/build_info.json`,
`dist/`, `py/.venv/`. **`_private/`** is gitignored too and holds real corpus captures — **client
data**, never committed.

## Before you change anything here

- `00_Context/CONSTRAINTS.md` is one page and every line was paid for.
- Ruby is **2.7**. `ruby -c` every file (`make build` does it for you).
- The dialog's JS targets **Chromium 88**, not your browser.
- The translator targets **Python 3.11** exactly — Pyodide 0.24.1's CPython. `py/.venv` matches it.
- `make ci` proves everything *except* `HtmlDialog` itself. Its threading and payload limits are
  reachable only from a SketchUp session, which is why every phase ends with a staged Ed runbook.
- ⚠ **`make ci` green is not evidence about designPH.** It was green throughout the session in which
  the first real capture found four defects it could not have caught — two of them design errors in
  the contract, two in the reconciliation harness itself. The corpus fixtures in `_private/` are what
  carry evidential weight; run against all five, never Adelphi alone
  (`00_Context/CONSTRAINTS.md` §9).
